# [게임최적화기법(2A)] 기말 과제 최종 보고서 (AI 협업 및 최적화 부문)

## 1. 에이전트 협업 개발 환경 설계 및 설정

본 프로젝트는 AI 에이전트(Antigravity 등)와의 협업 효율성을 극대화하고, 일관성 있는 고품질 코드를 유지하기 위해 아래와 같이 체계적인 개발 파이프라인 및 에이전트 룰셋을 사전에 정의하여 운용했습니다.

### 에이전트 규칙 파일 연동
- **프로젝트 루트 지침 (`AGENTS.md` / `.antigravityrules.md`)**: 전역 오염 방지(엄격한 로컬 캡슐화), `update`와 `draw` 책임의 분리, 그리고 성능 최적화(GC 최소화) 지침을 수립해 AI 에이전트가 코드를 설계하는 제약 조건으로 강제했습니다.
- **특화 하위 룰셋 (`.antigravity/rules/`)**:
  - `lua-expert.md`: Lua 5.1/LuaJIT 호환 문법 준수, nil 방어 코드 작성 및 타입 검증 규칙 명문화.
  - `lua-love2d.md`: LÖVE2D 엔진의 그래픽 파이프라인 제약과 렌더러 분리 표준 지정.

### 정적 분석 및 자동 포맷터
- **StyLua (`stylua.toml`)**: 코드 포맷의 통일성을 지켜 협업 시 Git Diff 가독성 개선.
- **Luacheck (`.luacheckrc`)**: 전역 범위 오염 여부와 미사용 변수를 컴파일 전에 탐지하여 빌드 안정성 확보.
- **VS Code 설정 (`.vscode/settings.json`)**: LÖVE2D 전역 API (`love`, `jit`, `utf8`)를 인식하도록 린터 구성을 맵핑하여 코드 작성 도중 불필요한 노이즈 진단 제거.

## 2. 에이전트 핸들링 전략 및 프롬프트 엔지니어링

AI 에이전트와의 협업 도중 발생할 수 있는 토큰 낭비 및 오작동을 예방하기 위해 구체적인 지시 프레임워크와 핸들링 기법을 도입했습니다.

### 주요 핸들링 전략
1. **맥락 쪼개기 (Scope Narrowing)**:
   - AI 에이전트에게 광범위한 리팩터링을 맡기지 않고, 구체적인 파일 경로와 변경 대상 함수/라인 범위를 명확히 지목해 소모되는 컨텍스트 창을 제한했습니다. (예: `project/src/enemy/spawner.lua 내 350~400라인에 대시 속도 제한을 수정해줘`)
2. **주기적 세션 리셋 (Session Reset)**:
   - 질문 턴수가 길어질 때마다 누적 토큰 요금을 아끼기 위해 대화를 새로 시작(New Chat)하고, 이전 세션의 성과는 저장소 내 `worklog` 요약을 통해 하나의 프롬프트로 전달해 맥락을 동기화했습니다.
3. **설명 생략 및 코드 중심 지시 (Concise Response)**:
   - "개념적 설명은 배제하고, StyLua 포맷에 맞춘 변경 사항 코드와 리팩터링 사유만 한 줄로 간결히 제시할 것"을 명시해 출력 토큰을 40% 이상 절감했습니다.

### 효과적이었던 프롬프트 예시
> *"spawner.lua의 Enemy.update에서 몬스터들을 소멸 처리할 때 테이블 인덱스가 깨지는 버그가 의심된다. 루프를 역순으로 돌리거나 예약 큐를 사용하도록 구조를 수정하고, 변경된 부분 외의 주변 변수 이름은 유지해라. 설명은 최소화해줘."*

## 3. 테스트/디버깅 프로세스 및 자가 검증

기능 구현 후 "동작 가능한 결과"를 입증하고 회귀 버그를 방지하기 위해 정교한 디버깅 및 테스트 프로세스를 구축했습니다.

### 테스트 하네스 (Automated Test Harness)
- **자체 단위 테스트 구성 (`project/tests/`)**:
  - `collision_test.lua`: AABB 충돌 알고리즘, 플레이어 대각선 이동 정규화 수식, 카메라 Lerp 추적 좌표 보정을 개별 검증하는 테스트 시나리오 작성.
  - `main.lua` (테스트 러너): LÖVE2D 자체 그래픽 창에서 단위 테스트 결과를 retro 터미널 스타일로 렌더링하고, 성공(PASS)과 실패(FAIL/ERROR)를 구분해 표시하도록 구현.
  - **테스트 실행 작업화**: `.vscode/tasks.json`에 `Love2D: Run tests` 태스크를 등록하여 단축키로 테스트 스위트 전체를 한 번에 검증 가능하도록 연동.

### 해결한 주요 결함과 디버깅 과정

1. **Thorns 패시브 발동 시 테이블 인덱스 손상 (Iterator Invalidation)**
   - **증상**: 플레이어가 피격 시 주변의 모든 적에게 광역 반사 피해를 주도록 하자 몬스터 배열을 순회하던 루프 도중 사망한 몬스터가 즉각 삭제되면서 인덱스가 어긋나거나 `nil index` 런타임 오류가 발생.
   - **해결**: 대미지 반사 처리를 루프 안에서 즉시 수행하지 않고, 타격 대상 적의 참조를 `game.pendingThornsAttackers` 큐에 버퍼링해 두었다가, 메인 업데이트 루프가 끝난 뒤 안전하게 병합 삭제하는 "지연 처리 큐(Deferred Process Queue)" 구조를 적용해 완벽히 버그를 해결.
2. **Chain 스킬의 자식 체인 유령화 (Cascading Decay)**
   - **증상**: 3레벨 이상 체인 스킬에서 첫 몬스터에 이어진 체인이 인근 몬스터로 연쇄 발사된 후, 첫 몬스터가 죽으면 연쇄된 자식 체인만 공중에 남아 렌더링되는 문제 발생.
   - **해결**: 자식 체인 구조체에 `parent` 지정을 기록하게 만들고, 매 프레임 업데이트 시 부모 체인의 생존 여부와 페이드 타이머 정보를 확인하여 부모가 소멸하거나 `fading`에 진입하면 자식 체인도 동기화되어 소멸하도록 "계단식 소멸 알고리즘"을 도입.
3. **플레이어 이동 속도 배율 복구 누락 오류**
   - **증상**: 4스테이지 보스의 EMP 속도 저하 디버프를 구현하기 위해 플레이어 속도 연산에 `speedMultiplier` 곱 연산을 가미했으나, 보스가 사라지거나 맵이 넘어가도 속도가 정상 복구되지 않는 현상 검출.
   - **해결**: `spawner.lua` 업데이트 초입 및 플레이어 이동 업데이트 단계마다 `player.speedMultiplier = 1.0`으로 기본 리셋 연산을 수행하도록 동적 복구 물리식을 주입하여 해결.

## 4. 코드 최적화 및 가비지 컬렉션(GC) 최소화 성과

LÖVE2D 모바일 이식 및 저사양 환경 구동을 감안하여 매 프레임 실행되는 루프 내에서의 최적화 수칙을 철저히 이행했습니다.

1. **로컬 캐싱 (Local Caching)**:
   - 매 프레임(update/draw) 빈번하게 호출되는 외부 수치 함수들과 LÖVE2D API(`love.graphics`, `math.sin`, `math.cos`, `math.random`)를 파일 최상단 또는 모듈 최상단에서 로컬 변수로 바인딩하여 전역 테이블 조회(Global lookup) 비용을 최대로 낮췄습니다.
2. **테이블 할당 최소화 (GC Press Avoidance)**:
   - 투사체 궤적 계산이나 잔상 이펙트 연출을 할 때 루프 안에서 매번 임시 테이블 `{ x = x, y = y }`을 생성하는 대신, 기존 인덱스의 원소를 재활용하거나 초기화 단계에서 생성해둔 정적 버퍼를 재사용하도록 최적화했습니다.
   - **배경 입자 테이블 풀링**: 6개 스테이지의 다양한 동적 입자(마그마 재, 사이버 보드 노드, 번개 스파크, 골든 스타, 시간 먼지 등)를 실시간으로 스폰/소멸시킬 때 발생하는 메모리 단편화와 가비지 컬렉션(GC) 병목을 예방하기 위해, 입자 배열을 초기 로딩(`initBackground`) 시점에 고정 크기로 스캐폴딩하고 루프 안에서는 좌표 경계 검출에 따라 소멸 대신 위치값 리셋(`elem.y = 0` 또는 `elem.y = world.height`)을 통한 재활용(Pooling)을 처리하여 GC 프레임을 대폭 개선했습니다.
3. **물리 계산 연산 최적화**:
   - `checkLineCircleCollision` 등 무거운 선분 투영(Projection) 연산의 경우 연쇄 충돌 판정 이전에 간이 AABB 필터링을 1차적으로 거치도록 설계하여 수백 마리의 적과 전자기 펜스가 존재해도 60 FPS 프레임 드랍이 없도록 최적화했습니다.

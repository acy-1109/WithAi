# 목적

R4(적 AI), R5(업적), R6(하이스코어 저장·불러오기) 구현 시 AI가 자주 어기는 비결정성(`math.random`), `GameModel` 결합, 파일 I/O 경계 위반을 사전에 차단한다.

# 점검 절차

1. **난수 결정성 점검 (R4)**: 적 AI와 게임 로직에서 `math.random` 및 `os.time` 을 직접 호출하지 않고, 외부에서 주입받은 `rng` 인스턴스만 사용하는지 확인한다.
2. **이벤트·입출력 경계 점검 (R5·R6)**:
   - 업적 Model 이 `GameModel` 을 수정하지 않고 `game:drainEvents()` 이벤트를 구독해 독립적으로 판정하는지 확인한다.
   - 하이스코어 Model 은 문자열 직렬화/역직렬화만 담당하고, 실제 파일 I/O(`io`, `love.filesystem`)는 `main.lua` 에서만 수행하는지 확인한다.
3. **결정성·복구 테스트 작성**:
   - 같은 시드로 2회 실행했을 때 적 AI 상태 전이와 결과가 완전히 동일한지 헤드리스 테스트를 포함한다.
   - 깨진 하이스코어 문자열 입력 시 에러로 죽지 않고 기본값으로 복구되는지 테스트를 포함한다.
4. **계층 검증**: 수정 후 `layer_check.lua src` 와 해당 헤드리스 테스트를 실행해 위반 0건과 전체 통과를 확인한다.

# 하지 말 것

- `models/` 내부에서 `math.random`, `io.*`, `love.*`, `print` 를 직접 호출하지 않는다.
- `GameModel` 안에 업적 판정 로직이나 파일 저장 코드를 직접 넣지 않는다.
- 동일 시드 2회 실행 테스트 없이 R4 완료로 간주하지 않는다.
